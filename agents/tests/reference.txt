2. Multilingual Extension (Bahasa, Vietnamese, Thai)

Estimated Time: Full Day (New work, not a minor refinement)

Scope Correction: Although the output schema in intake.py lists all five languages as valid values, the system prompt currently only contains actual detection guidance for Filipino, Cebuano, and English. Bahasa, Vietnamese, and Thai have no prompt-level guidance. This task involves writing new prompt logic.

Prompt Expansion Requirements

Add a short block of distinguishing words, markers, and rules per language to the system prompt following the pattern of the existing Filipino/Cebuano notes:

Language Detection Notes:

Bahasa Indonesia: Detect key transition and functional words such as "yang", "dan", "di", "ini", "untuk".

Vietnamese: Detect common words such as "và", "của", "là", "không", and look for characteristic diacritics (e.g., á, à, ộ, etc.).

Thai: Detect Thai script (non-Latin character set). This is highly distinct and easily separable by script alone.

Proper Noun Preservation (New Instruction):
Add this explicit instruction to the prompt for Vietnamese and Bahasa to prevent translation errors:

"Preserve all administrative location names (province, municipality, barangay/desa equivalents) exactly as written in the source language. Do not translate or romanize place names."

Testing & Evaluation Protocol

Prepare one test situation report for each language and run it through the process.

Verify that the Intake Agent correctly detects the language and extracts the location, hazard_type, and urgency fields without errors.

Run each test at least twice (the first pass identifies prompt gaps; the second pass confirms the fix).

Thai Evaluation: A lower model confidence is expected and acceptable. Because Thai is structurally different from your high-resource languages, do not over-invest trying to make it perfect. A lower, honest confidence score with a flagged mandatory human review is a successful outcome.

Priority If Time is Short

Bahasa Indonesia (Needed if you demo an Indonesia scenario)

Vietnamese (Crucial for the cross-border demo below; this is the highest priority)

Thai (Nice-to-have, non-blocking)

3. Cross-Border $PH \rightarrow VN$ Scenario

Estimated Time: Half Day

Value Proposition: This is your core ASEAN differentiator. It is the single scenario that proves EMMA is a regional intelligence tool rather than a localized Philippine application. Grand Finale judges will expect to see this feature highlighted.

Scenario Requirements

Input: A Vietnamese-language situation report describing meteorological/ground conditions consistent with Typhoon Kalmaegi approaching Vietnam after already making landfall in the Philippines.

Agent Behavior: The Regional Pattern Agent must retrieve the historical Kalmaegi PH event from Qdrant and surface the connection explicitly in its output:

"Same storm system made landfall in Alcoy, Philippines 36 hours prior. Flood escalation pattern suggests similar risk here."

Testing: Test this end-to-end at least 3 times before the demo. Cross-border retrieval relies heavily on your Qdrant seed data containing both the PH and VN events with compatible semantic structures.

Sample Test Input (Vietnamese)

Báo cáo tình hình [Province], Việt Nam
Bão Kalmaegi đang tiến gần sau khi đổ bộ Philippines.
Ước tính [X] hộ dân bị ảnh hưởng.
Cần sơ tán khẩn cấp khu vực ven biển.

Have Jamal or someone with Vietnamese proficiency review this input text before using it in the live demo. Presenting machine-translated Vietnamese in a live pitch in Danang carries high risk if a Vietnamese-speaking judge is on the panel.
